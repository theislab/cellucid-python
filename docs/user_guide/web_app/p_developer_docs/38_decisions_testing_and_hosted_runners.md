# Decision record: testing and hosted runners

This page answers: **"Why are the web app's tests built the way they are: why
does every browser spec run on a fixed device, why does no test sleep, why do
contracts count instead of timing, what did the hosted CI runners show
that a developer machine did not, and how is the site built, served and kept
from a stale cache?"** It records the decisions with their
dates, the runs and numbers behind them, what was tried and taken out, and
what is still open. How to run and write tests (the commands, the rules as a
list, the checklists) is {doc}`14_testing_ci_and_release_process`, and this
page does not repeat it. A story about the product that a test found belongs
to that product's record; a story about a runner, a fixture or a wait belongs
here. Update this page in the same change as the code it describes.

## At a glance

**Audience**
- Developers changing a test helper, the test runners, the CI workflow, a
  rule of the suites, the build, the worker bundles or the code cache, and
  anyone asking why a rule on the testing page exists.

**Time**
- 25 minutes; each table can be read alone.

**Prerequisites**
- {doc}`14_testing_ci_and_release_process`.

## What it does now

1. **Three suites.** `npm test` runs every contract file of `tests/` under the
   Node.js test runner (`scripts/run-web-tests.mjs`); `npm run test:browser`
   runs the Playwright specs of `tests/browser/`; `npm run test:worker-bundle`
   checks that the community-annotation Worker bundles. CI runs the contracts
   on three operating systems and three Node versions, and the specs in three
   engines.
2. **The contract runner bounds progress, not duration.** Each file runs in a
   process group of its own and is stopped only after finishing no test for
   5 minutes. Every file's process is started with a network guard that
   refuses any host but this machine's loopback.
3. **A contract waits for an event and counts work.** No fixed pause stands
   for a delivery, no clock threshold stands for a cost, and a test whose
   assertions follow from a plan holds the machine's measured rates
   (`assets/js/utils/machine.js`, `tests/helpers/machine-at-rest.mjs`).
4. **Every browser spec runs on a fixed device** (`tests/browser/helpers/device.mjs`):
   a simulated GPU timer, held machine rates, a held link, 4 cores and 8 GiB.
   The suite runs with one worker and no retries.
5. **A spec waits for the product's state.** Fixed sleeps, counted waits,
   `setOffline(true)` outside its helper and leaving-document handlers in a
   spec are each refused by a contract test that reads the specs' sources.
6. **Every context is watched** for a response from outside this machine
   (`outside-requests.mjs`) and for a click whose press and release a layout
   change split (`split-clicks.mjs`).
7. **Pixels are compared exactly in every cell**, after the inputs of the
   two frames and what they submitted to the GPU are asserted equal
   (`tests/browser/helpers/pixel-parity.mjs` allows no tolerance). Hosted
   macOS Firefox draws less, for time, and says so where it does
   (`tests/browser/helpers/hosted-gl.mjs`); what it draws it compares exactly.
8. **Shards are planned before they run.** The bounded runner
   (`scripts/run-browser-shard-bounded.mjs`) lists what it will pass to
   Playwright and refuses a selection other than the plan.
9. **A deployed page runs a content-addressed bundle.** Any name but
   loopback starts every worker from a bundle named by its content hash, and a
   page that outlived its build says so and offers **Reload**; the code cache
   answers a visit from the worker (the build section below).

## Decisions and why

(testing-decisions-contract-suite)=
### The contract suite

| Date | Decision | Why | Rules out |
|---|---|---|---|
| 2026-11-01 | A file path from a module URL is `fileURLToPath(new URL('…', import.meta.url))` | On Windows `.pathname` is `/D:/a/…`, which Node opens as `D:\D:\a\…`; three contracts read no file, and four more compared `\`-separated names (`path.relative()`, in `tests/helpers/source-files.mjs`) with `'app/…'`, on every Windows job (run 43106620008) | `.pathname` of a file URL |
| 2026-11-01 | The repository's `package.json` declares `"type": "module"` | Without it Node warned about each `.js` file it had to reparse (the token validators in `scripts/` among them), through `console.error`, and on Node 22 the warning landed inside a test that counts `console.error` calls | CommonJS by default for a `.js` file of the repository |
| 2026-11-01 | An exact power of ten is parsed from its literal, ``Number(`1e${n}`)`` | `Math.pow(10, -4)` is `9.999999999999999e-5` on Node 22, which made figure export's tick step for 0.001–0.003 jump from 5e-4 to 1e-3 | `Math.pow(10, n)` where the exact decimal is meant |
| 2026-11-01 | A test waits for the event it needs: what proves a delivery, a turn after work that is only promise continuations, a passage of time only when time is the subject, and for "nothing happens" what ends the work that could do it | Windows timers fire on a 15.6 ms tick and its message delivery is slower, so a pause that covered a delivery on Linux and macOS did not there: `BroadcastChannel` delivery outlasted the 20 ms the memory census test slept, and a range the page cache was handed had not arrived 10 ms later in `formats-io-contract` (run 41292953076, Node 22 and 24) | A fixed pause for a delivery; a bounded count of `setImmediate` turns for a port's message |
| 2026-11-01 | A link a test gives a reader is priced as the test means it, round trip included | The page cache is given one round trip of the link to answer, so a held range "read around" on a 1 ms link was fetched again on a runner whose page answered slower than 1 ms; the test now prices bytes dear on a 1 s link instead | A link so fast that the runner's own speed decides the plan |
| 2026-11-01 | The suite can be run under slow delivery and coarse timers before CI does (`scripts/slow-delivery-preload.mjs`: every port and channel message up to 25 ms late, in order; every timer on a 16 ms tick, in order) | At that day's HEAD it failed the range cache, notebook widget, served-store and reader-channel tests (a fixed pause or a bounded count of `setImmediate` turns waiting for a port's message) and left `viewer-embed-contract` hanging on a port its failed test never closed | Learning of a delivery race from a Windows job |
| 2026-11-01 | Closing a store stops every read made through it (`close-stops-reads-contract`) | Under the slow-delivery preload, once the tests above were fixed, `gene-read-every-source` ran forever after all its tests passed: a read the reader started in the background (the row pointers of a Zarr folder over HTTP, for a gene index it was keeping on disk) carried no signal and outlived the source's disconnect, retrying its host | A background read without the store's signal |
| 2026-11-01 | A test undoes what it set up in reverse order (`undoLater(t, undo)`, `tests/helpers/teardown.mjs`) | `node:test` runs a test's `after` hooks first registered first, so a test that faked `fetch` (or `Worker`, `window`, `document`) and then made a source with it put the real global back before the source was torn down, and the leftover read above went to the real network (`data.example.org`), retrying, and kept the test process from ever ending (the slow-delivery run, 2026-11-01) | Bare `t.after` for a fake that something made later still uses |
| 2026-11-01 | No contract test reaches the network: `scripts/network-guard-preload.mjs` is preloaded into every test file's process, refuses a request to any host but loopback before a DNS lookup, and fails the file when its process exits, naming each URL | The leftover reads above asked a real host after their test had ended, or the code caught the refusal and retried, and the tests passed | A test that passes or fails by a real host's answer; a refusal the code under test can swallow |
| 2026-11-01 | Virtual time counts zlib's thread-pool work (`tests/helpers/virtual-time.mjs`) | Node's `DecompressionStream` inflates off the event loop, where `process.getActiveResourcesInfo()` lists nothing, so the clock moved while a chunk was still inflating; a macOS runner that inflated slowly then counted a global heap read in 4 rounds instead of 3 | A virtual clock that advances while native work is in flight |
| 2026-11-01 | The contract suite bounds progress, not duration: a file is stopped only after finishing no test for 5 minutes (`scripts/run-web-tests.mjs`) | The shard-capacity contract took 166 s under load, past the suite's bound of 120 s a file (Measurements, below); a slower machine that is still finishing tests must not fail for its speed | A time limit per file |
| 2026-11-04 | A test whose assertions follow from a plan holds this machine's speed: every measured rate that feeds a plan is read through `assets/js/utils/machine.js` (`measureOf`) and held there by the test (`holdMachine`, `tests/helpers/machine-at-rest.mjs`) | An opening's plan weighs how fast chunks decode, how long making every cell's order takes, how fast a kept gene index was read and what an index pass's work cost. Measured, each follows how busy the machine is: `gene-sample-contract` "a fast link: file order" opened every cell in a `blocks` order when run beside pytest and R checks, and passed alone: its plan turns below about 600 decoded bytes a millisecond and the file's earlier tests measure about 6,600 on an idle machine, and an order whose sample brings the first gene 142 ms sooner (`orderPays`) turns likewise once its pass over 6,000 cells stalls for 20 ms | A plan assertion on rates the test did not set |
| by 2026-11-06 | A test whose host is a function in the test's own process holds the link too (`holdMachineAtRest({link: LINK_AT_REST})`) | Such a host has no time of its own, so the link measured is only how busy the machine is. `open-cells-folder-reuse` failed on a loaded Windows runner because its 900-cell opening took over no index of the 300 cells open before it (run 42180511574). It fails on every run with every interval timed 40 times longer: the first gene of the 900 cells is then priced at 14.7 s, genes are read for 8 of them, and the share opens in the file's cell order | A measured link where nothing but the machine's load is measured |
| by 2026-11-06 | A byte reader whose requests a test holds at a gate takes a clock of its own (`createByteReader(source, {clock: virtualTime().now})`) | Timed, a request held for as long as a busy machine takes to open the gate was a slow link's, and the reader read further ahead than the test's reads expected (`shared-reads-cancellation`, HDF5: 12 of 12 runs failed with intervals timed 400 times longer, none with the clock) | The real clock under a gated request |
| by 2026-11-06 | A contract about cost counts, it does not time (`blocksRun`, `tests/helpers/block-counts.mjs`: the blocks of JavaScript a piece of work runs, by V8's precise coverage; for a native pass, the input lengths it was given, ranges shifted, questions asked and the length of the timer each set). A test's own `timeout` is a fence for a hang, never a budget | A threshold on a clock is flaky by construction on a shared runner: a 1 MB publish of the community-annotation Worker measured 12.1 parses of CPU on one hosted job and 5 on a Mac (run 42129386525) | A CPU or wall-clock threshold in a contract |
| by 2026-11-06 | A test waits for the work, not for a number of turns of the event loop: a fake schedule hands the write's own promise back (`manualSchedule`, `tests/helpers/memory-history-database.mjs`), and a test with mocked timers ticks them once the code has set the timer it means to end | Crypto, zlib and file work run on other threads, so no count of `setImmediate` turns is enough for them | Counting turns for work done off the event loop |
| 2026-11-07 | Whoever starts a process in a group of its own forwards the signals to it: `scripts/run-web-tests.mjs` stops every file it started | A process started `detached` (so a hung test file can be stopped with everything it started) no longer hears the terminal's Ctrl-C or a canceled job's SIGTERM | A detached child left to outlive an interrupted run |
| 2026-11-07 | Starting a process is measured, never assumed: a test of a time bound times a short run first and scales from it (`tests/web-test-runner-contract.test.mjs`) | On a runner five times slower than its peers, starting Node and the network guard took longer than a margin chosen on a fast machine | A margin chosen on a developer machine |
| 2026-11-07 | A rate is judged only on a watchdog tick that came on time (`scripts/install-linux-engine-libraries.mjs`) | When the whole process paused past a measuring window, the timer ran before the bytes that arrived were read, and a healthy transfer looked empty | Judging a transfer on a late tick |
| 2026-11-12 | Two short sets answer first while the full suites stay the gate: `npm run test:core` (the core contract tests, by layer) and `npm run test:browser:smoke` (one walk from start to export in each engine), both lists in `scripts/test-suites.mjs` held to the tree by `tests/test-suites-contract.test.mjs` | On the development machine the contract suite took two minutes and the browser suite 107 minutes for the three engines, so nothing answered within a minute of a change | A short set as the gate; a change called done on the short sets alone |
| 2026-11-12 | No page code in a worker: `tests/worker-bundles-contract.test.mjs` refuses a worker whose import closure (types included) reaches the page's notices or interface components, and a bundle that names a page-only global (`document`, `window`, `localStorage` and the like) outside a `typeof` test. The reader worker no longer reads the sample catalog's page address and `document`: that read is `data/sample-catalog-config.js`, a module of the page, and the generation worker's `fromGLBUrl` takes the absolute URL the page resolves | A worker that reaches such a module fails only when that line runs, on the one input that gets there (a ReferenceError in a worker); the import closure shows it at once | A worker that reads the page's address, document or notices |
| 2026-11-12 | The JavaScript is type-checked from its JSDoc, and only the diagnostics that mean a defect whatever the typing style fail it everywhere; a folder that is clean of every diagnostic is declared fully checked and stays so | 5,035 diagnostics at the first run, 3,734 of them a member the checker cannot follow (methods mixed onto a prototype, fields added after construction): failing on all of them would mean rewriting the code's style, failing on none would check nothing. Of the 290 that mean a defect, 131 were JSDoc that said something untrue and four were real defects | A baseline file of counts to keep; `@ts-ignore` and its kin under `assets/js` |

### Browser specs: waiting for state

| Date | Decision | Why | Rules out |
|---|---|---|---|
| 2026-11-01 | The browser suite keeps `retries: 0` | A spec that pauses a fixed time for work it cannot see passes where that work is quick and fails where it is not, on another engine and shard from run to run; a retry would hide exactly these failures, and a red gate that teaches nothing but to re-run it slows every change and every upgrade | Retries as a cure for a race |

## Known limits and open items

- **The few pixels on hosted macOS Firefox are not explained.** That they are
  that renderer's rounding and nothing else has not been established: they
  were measured on the hosted cell only. No other cell has a bounded
  comparison.
- **Two pixels on hosted Windows Firefox.** Whether the first frame after a
  level change differs there by a defect of that renderer is not known; the
  spec reads steady frames and compares them for equality there as
  everywhere.
- **Where the pixel differences were first seen** (2026-11-01, not reproduced, causes
  unproven). `figure-export.spec.mjs` "the point pass drawn on the page equals the one drawn in
  the worker": on macOS Firefox the two rasters differed at 7 of 15,346 drawn pixels, by at most
  3 levels, all on antialiased rims, alpha included (so not a premultiplication round trip: both
  bitmaps are read through the same 2D canvas). Both are drawn by the same code with the same
  requested attributes in two WebGL2 contexts (an `OffscreenCanvas` on the page and one in the
  worker), so the two contexts are the only input left. The spec compares both contexts'
  descriptions (`rasterContext`: renderer, vendor, granted attributes, samples) before the
  pixels and attaches them with the first 32 differing pixels: the next failure names the input.
  If the contexts differ there, the contract is one context's pixels, not the same pixels from
  any two. `segmented-point-stores.spec.mjs` "flatumap", reduced level: on Windows Firefox 2
  pixels, both on row 359, differed between one store and segments of 4,096 points, with store
  bytes, cameras, level and cells drawn equal; the spec attaches the context (renderer, granted
  attributes, samples) and every draw of both frames (program, mode, first, count, vertex array,
  viewport) of a configuration that differs. On macOS Firefox both patterns timed out (600 s, the
  slow GL above).
- **A slow GPU's cost per pixel.** Only drawing fewer pixels could lower the
  per-frame cost on hosted macOS Firefox (a render scale or antialiasing
  chosen from the measured frame cost). That is a decision about how the
  picture looks, left to the owner.
- **A Chromium page that stops answering for about a minute on a loaded
  machine.** With the machine's load average between 85 and 316 (ten cores,
  other work beside three Playwright workers), a Chromium page now and then
  answered no `page.evaluate` for about 60 s (the spec's 60 s poll for its
  open cells then ended at 0) and went on afterwards: 2 of 198 runs of
  `open-cells-in-place`, `kept-gene-index` and `kept-parts` on main
  (e0aaaebc5), 13 of 426 on the branch that holds the machine, none of 140 in
  Firefox or 176 in WebKit. The page had started (its viewer made, in one
  trace its first frame drawn) and the reads resumed by themselves. Not
  traced; a hosted runner runs one worker, and no CI run of these specs on
  Chromium failed so in the forty runs looked at.
- **A backdrop's sky under a slow GPU** is not verified for every spec: the
  look shows from its first level on any GPU, and a slow one stops refining
  sooner (a coarser sky), so a spec may assert a look only against the same
  page.
- **A green repeat is evidence, not proof.** A machine that is not a hosted
  runner does not show every runner's race, and the local software-GL
  project is faster than a hosted runner, so a race that needs a runner's
  speed may still not show.
- **A page opened as a deployed site measures everything.** It runs its
  bundle, whose module instances an init script cannot name, so the device's
  holds do not reach it and a spec opened there asserts nothing that follows
  from a plan.
- **The macOS WebKit abort in a page closed soon after it showed an http
  page is Apple's.** An observer of the Screen Time controller is removed on
  the main thread while its XPC reply is applied (Apple FB21537703; WebKit bug
  303024 made the queue serial, which does not order it against the main
  thread), and the browser aborts in that close. It was seen in a Web contracts
  run (macOS 26.7.2, WebKit r2388). The download probe runs on `about:blank`,
  where the observer never starts, and the Learn more window is given a
  refused page for the same reason.
- **Where a non-finite coordinate in Playwright's WebKit comes from is not
  known.** The watcher on every context names the event when it happens.
- **Whether GitHub Pages purges its CDN on a deploy is not measured.** If it
  does not, a page loaded within ten minutes of a deploy can receive a file's
  previous bytes at its new URL; a mismatch that fails to link is shown as
  **Cellucid has been updated**.
