# Decision record: the interface

This page answers: **"Why does the interface behave the way it does: the
sidebar and its controls, dialogs and menus, legends, the phone layout, the
keyboard and focus, notices and their wording, the camera path and the chat
bar, the benchmark panel, startup and community annotation?"**
It records the decisions with their dates, what each replaced, and what is
still open, one section a surface. Which module owns what is
{doc}`08_ui_modules_map`, and this page does not repeat it. Decisions about
what is drawn in the plot are in {doc}`28_decisions_rendering_layers`; about
a figure, in {doc}`36_decisions_figure_export`; about an analysis panel, in
{doc}`37_decisions_analysis`. Update this page in the same change as the code
it describes.

## At a glance

**Audience**
- Developers changing `app/ui/` (except figure export), the app's root
  modules, `app/community-annotations/`, or a notice or a sentence the app
  says. The build, the worker bundles and the code cache are
  {doc}`38_decisions_testing_and_hosted_runners`.

**Time**
- 30 minutes; each table can be read alone.

**Prerequisites**
- {doc}`08_ui_modules_map`.

## What it does now

Paths are under `cellucid/assets/js/app/` unless they name another place.

1. **One thin coordinator** (`ui/core/ui-coordinator.js` `initUI`) collects
   the DOM references once (`ui/core/dom-cache.js`), starts the feature
   modules and wires the callbacks between them. A module owns its DOM
   subtree.
2. **A control dispatches the action it stands for** and calls no mutating
   state method itself; settings controls and camera gestures are recorded
   by observation ({doc}`29_action_layer_domains_and_history`).
3. **The control inventory is read from the markup**
   (`state-serializer/ui-controls.js`): an `input` or `select` with a stable
   id is a setting the history records, a session saves and an agent can
   set, with no code.
4. **Panels dock, float and move** (`dockable-accordions.js`), by pointer
   and by keyboard (`ui/keyboard-move.js`); where each stands is the `layout`
   state domain's.
5. **One table holds every keyboard shortcut**
   (`ui/onboarding/shortcut-table.js`); the shortcuts page of the user guide
   is written from it.
6. **One notification center** says what the app is doing and what failed
   (`notification-center.js`), with one sentence a cause.
7. **On a phone the sidebar is a sheet** over the plot
   (`ui/core/phone-sheet-memory.js`, `ui/core/viewport-init.js`); the sheet
   is page chrome, never a history step.
8. **Community annotation** keeps one file a user in a GitHub repository,
   through a GitHub App and a Cloudflare Worker (`community-annotations/`).
9. **The page starts its code only once it is styled** (the style gate in
   `cellucid/index.html`), and a stylesheet or a module that did not load is
   reported on one failure screen (`startup-failure.js`).
